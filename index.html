Chapter 1 · the big pictureWhy data mining — and what it actually is

Why we care The world stopped running out of data a long time ago. E-commerce, web transactions, remote sensors, bioinformatics, YouTube uploads — every domain now drowns in it. The problem flipped: not "how do we get data?" but "we have too much — how do we find the useful patterns buried in it?" That gap is what data mining exists to fill.

What is data mining?

📌 Definition — memorise the four adjectives Data mining is the extraction of interesting — that is, non-trivial, implicit, previously unknown and potentially useful — patterns or knowledge from huge amounts of data. The four words in bold are worth marks; examiners pick them out one by one.

It goes by many other names, and any of them can appear in a "give alternative names" question: knowledge discovery from/in databases (KDD), knowledge extraction, data/pattern analysis, data archaeology, data dredging, information harvesting, and business intelligence.

Data mining = digging previously-unknown patterns out of a mountain of data. If you already knew it or could just look it up, it isn't mining.

What is not data mining?

This contrast is a favourite short question. The trick: a plain lookup or query retrieves facts that are already stored and known. Data mining discovers patterns nobody put there on purpose.

NOT data mining (simple retrieval)IS data mining (pattern discovery)
Look up a phone number in a directoryDiscover that certain surnames cluster by region (O'Brien, O'Reilly… concentrate around Boston)
Query a search engine for "Amazon"Discover groups of similar documents on the web
🎯 Exam tip "Differentiate data mining from a database query." Answer in one sentence: a query returns what is already known and stored; data mining uncovers new, implicit patterns the data was never explicitly labelled with.

Chapter 1 · the pipelineKnowledge discovery (KDD) — the steps

Why we care Data mining is not one magic button — it's one step inside a longer pipeline called Knowledge Discovery from Data (KDD). Slides often use "data mining" and "KDD" as synonyms, but strictly, mining is the core step and KDD is the whole journey from raw data to usable knowledge.
📌 The 7 KDD steps (from the textbook) — in order 1. Data cleaning (remove noise, fix inconsistencies) → 2. Data integration (combine multiple sources) → 3. Data selection (pick the relevant data) → 4. Data transformation (normalise / aggregate into mineable form) → 5. Data mining (apply the algorithm to extract patterns) → 6. Pattern evaluation (keep only the genuinely interesting patterns) → 7. Knowledge presentation (visualise / report it).
Steps 1–4 are all preprocessing (that's the whole of Chapter 2 Part B!), step 5 is the actual mining, steps 6–7 turn patterns into knowledge. Clean → Integrate → Select → Transform → Mine → Evaluate → Present.

The lecturer's shorter "data mining process"

The slides also give a compact 4-step working loop for a single mining project:

  1. Understand the domain — know the problem you're solving.
  2. Create a dataset — select the interesting attributes, then clean and preprocess.
  3. Choose the data-mining task and a specific algorithm.
  4. Interpret the results — and if they're weak, loop back to step 2.
🎯 Exam tip If a question says "explain the steps of knowledge discovery," give the 7-step KDD list and note that data mining is the essential core step, not the whole process.

Chapter 1 · task in focusClassification

📌 Definition Given a training set of records where each record has several attributes and one of them is the class, classification finds a model for the class attribute as a function of the other attributes. The goal: assign a class to previously unseen records as accurately as possible. A separate test set measures that accuracy.
💡 Think of it like… A tax office deciding whether a return is likely to "cheat". It learns from past returns (with the cheat/no-cheat label known) which combinations of Refund, Marital status and Income tend to cheat, then applies that learned decision tree to a new return whose label is unknown.

The workflow: split the data into a training set (build the model) and a test set (validate it), learn a classifier (e.g. a decision tree), then push a new record down the tree to read off its predicted class.

🎯 Exam tip — the classic contrast Classification is supervised (classes are predefined and the training data is labelled). Clustering is unsupervised (no predefined classes — the groups emerge from similarity). Mixing these up is the single most common mistake here.

Chapter 1 · task in focusClustering

📌 Definition Given a set of data points (each with attributes) and a similarity measure, clustering finds groups such that points in one cluster are more similar to each other, and points in separate clusters are less similar. There are no predefined classes — the groups are discovered.
Good clustering = intra-cluster distance minimised, inter-cluster distance maximised (tight groups, far apart). For continuous attributes the usual similarity measure is Euclidean distance.
✍️ Example — document clustering Goal: group documents that are similar. Approach: find the frequently-occurring terms in each document, build a similarity measure from those term frequencies, and cluster on it. Gain: information retrieval can then relate a new document or search term to the right cluster.
🎯 Exam tip Clustering is descriptive and unsupervised. If asked "how does clustering differ from classification," lead with: clustering has no class labels — it invents the groups.

Chapter 1 · task in focusAssociation rule discovery

📌 Definition Given a set of records, each containing some items from a collection, association rule mining produces dependency rules that predict the occurrence of an item based on the occurrence of others.
💡 Think of it like… Supermarket market-basket analysis: looking at thousands of receipts to learn "people who buy X tend to also buy Y", so you can place them together or recommend one from the other.
✍️ Example — the classic baskets From transactions like {Bread, Coke, Milk}, {Beer, Bread}, {Beer, Coke, Diaper, Milk}… the miner discovers rules such as {Milk} → {Coke} and {Diaper, Milk} → {Beer}.
🎯 Exam tip Association is a descriptive task. The famous (if apocryphal) result to quote is the diaper → beer rule — it shows a pattern nobody would have guessed, which is exactly the point of mining.

Chapter 2A · start hereWhat is "data", really?

Before we can mine data, we need to agree on what data even looks like. Forget anything scary — a dataset is just a table, exactly like an Excel sheet.

💡 Think of it like… A class attendance register. Each row is one student. Each column is one fact about that student — name, roll number, age, marks. That's literally all a dataset is.

In data-mining language we give those two things fancy names:

  • A data object = one row = one "thing" you're studying (one student, one customer, one patient). You'll also hear it called a sample, instance, record, data point, or tuple — all the same idea, don't let the synonyms scare you.
  • An attribute = one column = one property of that thing (age, colour, marks). Also called a feature, dimension, or variable.
🎯 Exam tip If asked "what is a data object / attribute", the one-liner is: rows are data objects, columns are attributes. Give an example (a student row; an "age" column) — examples get you the full mark.

The heart of the chapterThe 5 attribute types

Why we care This is the single most important idea in the whole "getting to know your data" chapter. The type of an attribute decides what maths you're allowed to do with it. You can find the "average colour" of nothing — but you can average ages. Get the type right and half the chapter falls into place.

1. Nominal — just names

Nominal attributes are pure labels: categories with no order and no maths.

💡 Think of it like… Jersey numbers or eye colour. Player #10 isn't "more" than player #7 — the number is just a name. Blue isn't greater than brown. Examples: hair colour, marital status, zip code, ID number.

2. Binary — a yes/no switch

A binary attribute is a nominal attribute with exactly two states, written 0 and 1. But there's a subtlety the exam loves:

  • Symmetric binary — both outcomes matter equally, and swapping 0↔1 changes nothing. Gender is the classic example.
  • Asymmetric binary — one outcome is rare/important and the other is boring. A disease test: "positive" is the meaningful, rare case; "negative" is the default. Convention: give the important/rare outcome the 1 (e.g. HIV-positive = 1).
⚠️ Remember this Symmetric vs asymmetric feels like a footnote now, but it completely changes the distance formula later (asymmetric measures throw away the "both are 0" cases). Lock it in here.

3. Ordinal — ranked, but gaps unknown

Ordinal attributes have a meaningful order, but you don't know how far apart the steps are.

💡 Think of it like… T-shirt sizes {Small, Medium, Large}. You know L > M > S, but "how much" bigger is L than M? No idea — the gaps aren't measured. Same with grades (A, B, C) and army ranks.

4 & 5. Numeric — Interval vs Ratio

Numeric attributes are actual measurable quantities. They split into two, and the whole difference is one word: zero.

📌 The one distinction Interval: ordered, equal-sized steps, but no true zero — zero doesn't mean "none". e.g. temperature in °C (0°C isn't "no heat"), calendar dates. You can add/subtract, but ratios are nonsense (20°C is not "twice as hot" as 10°C).

Ratio: everything interval has, plus a real zero that means "nothing". e.g. Kelvin, length, weight, money, counts. Now ratios work: 10 kg is twice 5 kg.
💡 The zero test Ask: "does 0 mean there is none of it?" 0 kg = no weight → ratio. 0°C = still plenty of cold air → interval. That one question separates them every time.

Bonus: discrete vs continuous

A separate slicing of numeric data: discrete = countable, gaps between values (zip codes, number of children — you can't have 2.5 kids). Continuous = real numbers, infinitely fine (height, weight, temperature). Binary is just a special discrete case.

Describing data · part 1Averages — where's the middle?

Why we care You've got 500 numbers. Nobody can eyeball 500 numbers. You want one number that says "this is the typical value". That's a measure of central tendency. There are three main ones and they answer slightly different questions.

Mean — the balancing point

The mean is the plain average: add everything up, divide by how many.

Mean x̄ = 1N (x₁ + x₂ + … + x_N)

Two variations worth knowing: a weighted mean gives some values more importance (like credit hours weighting your GPA) — you multiply each value by its weight, sum, then divide by the total weight. A trimmed mean chops off the highest and lowest few values before averaging, so a couple of extreme numbers can't wreck it.

Median — the true middle

Line all the values up in order; the median is the one in the middle (if there's an even count, average the middle two).

💡 Why the median matters Imagine 9 people in a room earning ₹20k each, and then a billionaire walks in. The mean salary now says everyone's rich — one huge value dragged it up. The median barely moves and still says "₹20k-ish". That's why we report median income, not mean: it's robust to extreme values.

Mode — the most popular

The mode is simply the value that appears most often. Data can have one mode (unimodal), two (bimodal), etc. It's the only average that makes sense for nominal data — the "most common hair colour" is a mode.

There's also the midrange = (min + max)/2, a quick-and-dirty centre, and a handy rule linking the three for slightly skewed data:

Empirical rule mean − mode ≈ 3 × (mean − median)
🎯 Exam tip "Mean vs median for skewed / outlier-heavy data → use the median, it's robust." That sentence is a free mark; be ready to say why (the mean gets dragged by extremes).

Describing data · part 3Spread — how scattered is it?

Why we care Two classes can both average 60 marks. In one, everyone scored 58–62; in the other, half scored 20 and half scored 100. Same average, totally different story. Dispersion measures capture that "spread" the average hides.

Range and quartiles

The simplest is the range = max − min. Trouble is, one freak value blows it up. So instead we chop the sorted data into four equal groups; the three cut points are the quartiles:

  • Q1 (first quartile) = the value 25% of the way up — a quarter of the data is below it.
  • Q2 = the median (50%).
  • Q3 (third quartile) = 75% of the way up.
💡 Think of it like… Exam percentiles. "You're in the 75th percentile" means 75% scored below you — that's Q3. Quartiles are just the 25/50/75 percentile marks.

The star measure is the Inter-Quartile Range:

IQR = Q3 − Q1
Remember: IQR = width of the middle 50%. Outlier rule of thumb: a value is suspicious if it sits more than 1.5 × IQR below Q1 or above Q3.

It's the width of the middle 50% of your data, so it completely ignores the wild extremes at both ends — a much sturdier spread than the range. It also gives us the standard outlier rule: a value is suspicious if it's more than 1.5 × IQR beyond a quartile (below Q1 − 1.5·IQR or above Q3 + 1.5·IQR).

Variance and standard deviation

Quartiles are position-based. The other family measures spread around the mean. The idea: for each value, measure its distance from the mean, and average those distances. We square the distances (so plus/minus don't cancel), and that average is the variance:

Variance σ² = 1N Σ(xᵢ − x̄)²  =  1N Σxᵢ² − x̄²

Because we squared, the units are weird (marks²). So we square-root it back to normal units and get the standard deviation, σ — the headline "typical distance from the mean":

Std. deviation σ = √(σ²)
Remember: variance = average squared distance from the mean; σ = its √ (back to real units). Fast hand-form: mean of the squares − square of the mean.
🎯 Exam tip The right-hand form (Σxᵢ²)/N − x̄² is the fast one for calculations — you only pass through the data once. σ = 0 happens only when every value is identical (no spread at all).

Describing data · part 4The five-number summary & boxplot

Bundle the key positions together and you get the five-number summary: min, Q1, median, Q3, max. Draw it and you get a boxplot — the quickest way to see a distribution's shape and spot outliers.

How to read it: box = middle 50%, line inside = median, whiskers = the reach of "normal" data, dot = outlier.

Reading it top to bottom: the box spans Q1→Q3 (that's the IQR), the line inside is the median, the whiskers stretch out to the furthest points still within 1.5×IQR, and anything past that gets its own dot as an outlier. One glance tells you the centre, the spread, and whether anything weird is going on.

Comparing objects · part 1Similarity & distance

Why we care Almost all of data mining boils down to one question: "how alike are these two things?" Recommending movies ("people similar to you liked…"), grouping customers, search — all of it needs a number for closeness. That number is either a similarity or a distance.
  • Similarity — bigger = more alike. Usually squeezed into [0, 1], where 1 means "identical".
  • Dissimilarity (a.k.a. distance) — smaller = more alike. Usually starts at 0 (an object is distance 0 from itself).
  • Proximity is just the umbrella word for "either of those".

They're two sides of one coin: often similarity = 1 − distance.

📌 Two matrices you'll be asked about Data matrix — the raw table, n objects × p attributes. It's two-mode (rows and columns are different kinds of thing: objects vs features).

Dissimilarity matrix — an n×n grid holding the distance between every pair of objects. It's single-mode (objects on both axes). Since distance(i,j) = distance(j,i) and distance(i,i)=0, we only bother filling the lower triangle, with zeros down the diagonal.

Comparing objects · part 2Distance for nominal data

Nominal values are just names, so "distance" can only mean one thing: do they match or not? Count the matches and compare to the total.

Simple matching d(i, j) = p − mp

where p = total number of attributes and m = how many of them match. So the distance is just "the fraction that disagree". Similarity is the flip side, m/p.

✍️ Quick example
1. Given: two people described by p = 5 nominal attributes, of which m = 2 match.
2. Distance: plug into d = (p − m) / p → (5 − 2) / 5 = 3/5 = 0.6.
3. Similarity: the flip side, m / p → 2 / 5 = 0.4 (and 1 − 0.6 = 0.4 ✓).
4. Read it: more matches → smaller distance. Makes sense.

Comparing objects · part 3Binary data & the Jaccard coefficient

When every attribute is a 0/1, we compare two objects by tallying how their bits line up in a little 2×2 contingency table:

j = 1j = 0
i = 1q (both 1)r (i has it, j doesn't)
i = 0s (j has it, i doesn't)t (both 0)

So q = attributes where both are 1, r and s = the mismatches, t = where both are 0. Now the distance depends on whether the attributes are symmetric or asymmetric:

Symmetric d = r + sq + r + s + t
Asymmetric d = r + sq + r + s   ·  Jaccard sim = qq + r + s = 1 − d
💡 Why asymmetric throws away t Think of a rare disease. Two people who both don't have it (a 0-0 match, that's t) share nothing meaningful — almost everyone doesn't have it. Counting those would make everybody look "similar". So for asymmetric data (and Jaccard) we drop t and only reward shared presence (q) versus mismatches (r, s).
✍️ Worked example — straight from your slides

Gender is symmetric, so we drop it; the six tests are asymmetric binary. Let Y/P = 1 and N = 0, then use d = (r+s)/(q+r+s).

Comparing objects · part 4Distance for numbers: Minkowski

For numeric data, distance means actual geometric distance. The general formula is Minkowski, and the exam really tests its two special cases.

Minkowski (order h) d(i, j) = ( Σ |xᵢf − xⱼf|ʰ )1/h

You don't usually plug in weird h values — you pick one of these two:

📌 The two you must know h = 1 → Manhattan distance (L1): just add up the absolute differences. d = Σ|xᵢf − xⱼf|.
h = 2 → Euclidean distance (L2): the straight-line distance from school geometry. d = √(Σ(xᵢf − xⱼf)²).
💡 Manhattan vs Euclidean Imagine walking between two street corners in a city grid. Euclidean is the crow-flies straight line through the buildings. Manhattan is how you'd actually walk — along the blocks, left and then up. That "city block" walk is where the name comes from. (A third, L∞, takes the single biggest coordinate difference.) And on 0/1 vectors, Manhattan has a special name — the Hamming distance, the number of positions where the two binary strings differ.
🎯 Exam tip — the metric properties A distance is called a proper metric if it obeys three rules: (1) positive definiteness — d(i,j) > 0 for different points and d(i,i)=0; (2) symmetry — d(i,j)=d(j,i); (3) triangle inequality — d(i,j) ≤ d(i,k)+d(k,j) (no shortcut through a third point). These three are a classic short-answer question.
✍️ Worked example — 4 points

Points x1=(1,2), x2=(3,5), x3=(2,0), x4=(4,5). Distance = how far apart on the grid.

1. Subtract each coordinate. For x1=(1,2) and x2=(3,5): |1−3| = 2 and |2−5| = 3.
2. Manhattan (h = 1): just add the differences → 2 + 3 = 5.
3. Euclidean (h = 2): square them, add, take the root → √(2² + 3²) = √(4 + 9) = √13 = 3.61.
4. Same steps, x3 → x4: differences |2−4| = 2 and |0−5| = 5. Manhattan = 2 + 5 = 7; Euclidean = √(4 + 25) = √29 = 5.39.

Comparing objects · part 5Cosine similarity (for documents)

Why we care How do you measure if two documents are about the same thing? Turn each into a vector counting how often each word appears. But a long article and a short note on the same topic have very different word counts — plain distance would call them "far apart" just because one is bigger. We want to compare direction, not size.
💡 Think of it like… Two arrows. Cosine similarity measures the angle between them, ignoring their length. Pointing the same way (angle 0°) → cosine = 1 (identical topic). At right angles (share no words) → 0. Length doesn't matter, only direction — perfect for documents.
Cosine cos(d1, d2) = d1 · d2‖d1‖ ‖d2‖
Remember: “dot over lengths.” Top = multiply matching entries and add; each length = √(sum of squares). Measures angle, not size → 1 = same topic, 0 = perpendicular.

where d1 · d2 is the dot product (multiply matching entries, add them up) and ‖d‖ is the length of the vector (√ of the sum of its squares).

✍️ Worked example — straight from your slides

Two documents written as word-frequency vectors:

d1 = (5, 0, 3, 0, 2, 0, 0, 2, 0, 0)
d2 = (3, 0, 2, 0, 1, 1, 0, 1, 0, 1)
1. Dot product (top of the fraction): multiply matching entries and add them. Only positions where both are non-zero count: 5·3 + 3·2 + 2·1 + 2·1 = 15 + 6 + 2 + 2 = 25.
2. Length of d1: square each entry, add, take the root → √(5² + 3² + 2² + 2²) = √(25+9+4+4) = √42 ≈ 6.481.
3. Length of d2: same again → √(3² + 2² + 1² + 1² + 1² + 1²) = √(9+4+1+1+1+1) = √17 ≈ 4.123.
4. Divide: cosine = 25 / (6.481 × 4.123) ≈ 25 / 26.72 ≈ 0.94.
5. Meaning: 0.94 is very close to 1 → the two documents are highly similar in content.

Preprocessing · step 1Data cleaning — missing values & noise

Cleaning tackles three ailments: missing values, noisy values, and inconsistencies. Let's take them in turn.

Handling missing values — the 6 methods

Why we care Blanks are everywhere (a customer left "income" empty). Many algorithms can't handle a blank at all, and how you fill it changes your results — so this is a core skill, and a classic "describe the methods" question.
  1. Ignore the tuple. Drop the whole row. Easy, but wasteful — only sensible when the class label is missing or the row has many blanks.
  2. Fill in manually. A human enters the value. Most accurate, but slow and impossible at scale.
  3. Use a global constant. Replace every blank with one label like "Unknown" or −∞. Simple, but the miner may treat "Unknown" as a real, meaningful category — not recommended.
  4. Use a measure of central tendency (mean for symmetric data, median for skewed data). E.g. fill missing income with the average income.
  5. Use the attribute mean/median for the same class. Fill a missing income with the average income of customers in the same credit-risk group — smarter than a global mean.
  6. Use the most probable value. Predict it from the other attributes using regression, Bayesian inference, or decision-tree induction. Most sophisticated and usually most accurate.
🎯 Exam tip If asked for "the best" method, say #6 (most probable value via regression/decision tree) — it uses the most information. If asked which is not recommended, say #3 (global constant).

Noisy data & smoothing

📌 Noise Noise = a random error or variance in a measured value (a scale that wobbles, a typo of 520 for 52). Smoothing removes noise so the underlying trend shows through. Three main techniques: binning, regression, outlier analysis (clustering).

Binning

Sort the values, chop them into bins (buckets), then smooth each bin locally by consulting its neighbours. Two ways to cut the bins, three ways to smooth:

  • Equal-depth (equal-frequency): every bin holds the same number of values.
  • Equal-width: every bin covers the same value range (interval width).
  • Smooth by bin means (replace all with the bin's mean), bin medians, or bin boundaries (replace each value with whichever boundary — min or max — it's nearer to).
✍️ Worked example — smoothing by bin means, depth 3

Age data (already sorted): 13, 15, 16, 16, 19, 20, 20, 21, 22, 22, 25, 25, 25, 25, 30, 33, 33, 35, 35, 35, 35, 36, 40, 45, 46, 52, 70. Use equal-depth bins of depth 3 and smooth by bin mean.

Step 1 — sort. Already sorted, so skip.
Step 2 — partition into bins of 3. Bin 1: 13,15,16 · Bin 2: 16,19,20 · Bin 3: 20,21,22 · Bin 4: 22,25,25 · Bin 5: 25,25,30 · Bin 6: 33,33,35 · Bin 7: 35,35,35 · Bin 8: 36,40,45 · Bin 9: 46,52,70.
Step 3 — mean of each bin. 14.67, 18.33, 21, 24, 26.67, 33.67, 35, 40.33, 56.
Step 4 — replace every value with its bin mean. Bin 1 → 14.67, 14.67, 14.67; Bin 3 → 21, 21, 21; Bin 9 → 56, 56, 56; and so on.
Comment: this is local smoothing — each value is pulled towards its neighbours, flattening small wobbles while keeping the overall rising trend.
⚠️ Common mix-up Equal-depth = equal count per bin; equal-width = equal range per bin. They give different bins for the same data. And "smoothing by bin means" ≠ "by boundaries" — means replaces with the average, boundaries snaps each value to the nearer end of the bin.

Outlier analysis

📌 Outliers by clustering An outlier is a value that sits far from the rest. A neat way to find them is clustering: group similar values into clusters; anything that falls outside every cluster is a candidate outlier. (The lecture's "customers in a city forming 3 clusters, with a few stragglers outside" is exactly this picture.)

Other smoothing you can name: regression (fit the data to a line/curve so the fitted value replaces the noisy one) and concept hierarchies (roll low-level values up to higher-level concepts).

Preprocessing · step 2Data integration & redundancy

Why we care Your data lives in many places — a sales DB, a spreadsheet, a web log. To mine it together you must merge them into one store. Do it carelessly and you get clashes, duplicates and redundant columns that mislead the miner.
📌 Data integration — the three issues
  1. Schema integration & entity identification. Match up equivalent real-world entities across sources — is cust_id in DB1 the same thing as customer_no in DB2? (The entity identification problem.)
  2. Redundancy. An attribute may be derivable from others (e.g. age from birth-date), or the same attribute may appear under different names. Redundancy is detected by correlation analysis.
  3. Detection & resolution of value conflicts. The same entity may have different values across sources due to different units, scales or encodings (₹ vs $, kg vs lb).

Detecting redundancy with correlation

Two columns that move together are likely redundant — keep one. For numeric attributes we measure this with the Pearson correlation coefficient:

Pearson r rA,B = Σ(ai−Ā)(bi−B̄)n · σA · σB
Remember: “co-movement over spread.” Top = do A and B move together (both above/below their means)? Bottom scales it by their sizes. Sign of r = the sign of that top sum: + together, − opposite, 0 unrelated.
📌 Reading r r > 0 → positively correlated (A rises, B rises) — the higher r, the more redundant. r = 0 → independent. r < 0 → negatively correlated (one up, other down). r lies in [−1, +1]. Correlation does not imply causation.

The related covariance tells you the direction of the joint variation: Cov(A,B) = Σ(aᵢ−Ā)(bᵢ−B̄)/n, and r = Cov(A,B) / (σAσB). Positive covariance → they tend to move the same way.

✍️ Worked example — correlation of age vs %fat

For 18 adults, measuring age against body-fat %, the Pearson coefficient comes out to r = 0.82 (verified independently).

Interpretation: r = 0.82 is strongly positive — as age goes up, body-fat % tends to go up too. The two attributes carry overlapping information, so for mining you might keep just one. Because r > 0, their covariance is also positive.
📌 For nominal data — the χ² test Correlation between two categorical attributes is tested with chi-square (χ²):
χ² = Σ (observed − expected)²expected
A large χ² means the two attributes are related (not independent). Same idea, different data type.
🎯 Exam tip Match the tool to the type: Pearson r / covariance → numeric; χ² → nominal. Mixing those up is an easy mark to lose.

Preprocessing · step 3Data reduction

Why we care Mining a massive dataset can take forever. Data reduction produces a much smaller representation that gives almost the same mining results — same answer, far less work.

It comes in a few flavours (know the names — they're recall questions):

  • Dimensionality reduction — fewer columns/attributes. Via attribute subset selection, or transforms like PCA (principal components) and wavelet transforms.
  • Numerosity reduction — fewer rows. Parametric (store a model's parameters instead of the data — e.g. regression, log-linear models) or non-parametric (histograms, clustering, sampling).
  • Data compression — encode the data in fewer bits (lossless or lossy).

Attribute subset selection

📌 Three greedy strategies Goal: drop irrelevant/redundant attributes.
  • Stepwise forward selection — start empty, keep adding the best remaining attribute.
  • Stepwise backward elimination — start with all, keep removing the worst.
  • Combination — do both: add the best and remove the worst each round.
(A decision tree can also select attributes — those it never splits on are dropped.)

Sampling — pick a representative subset of rows

📌 Four sampling methods
  • SRSWOR — Simple Random Sample Without Replacement: draw n rows, none repeats.
  • SRSWR — Simple Random Sample With Replacement: after drawing a row, put it back — it can be drawn again.
  • Cluster sampling — the data is already in groups (clusters); randomly pick whole clusters.
  • Stratified sampling — split into strata (e.g. young/middle-aged/senior) and sample from each, so every group is represented proportionally.
💡 Stratified, intuitively If a class is 70% first-years and 30% seniors, a fair survey samples both groups in that ratio — that's stratified sampling. It avoids accidentally polling only seniors.
⚠️ Common mix-up WOR vs WR: "without replacement" = no row twice; "with replacement" = a row can be picked again. One letter, whole marks.

Preprocessing · step 4Transformation & normalization

Why we care Suppose income runs 10,000–100,000 and age runs 0–100. In a distance calculation, income's huge numbers would completely drown out age — not because it matters more, just because its units are bigger. Normalization rescales every attribute to a common range so each gets a fair say.
💡 Think of it like… grading exams out of different totals — one test out of 20, another out of 100. To compare fairly you convert both to percentages. Normalization is exactly that: put every attribute on the same scale.

The three normalization methods

Min-max v′ = v − minAmaxA − minA · (new_max − new_min) + new_min

Linearly maps the data into a chosen range (often [0, 1]). Preserves the shape of the original distribution.

Z-score v′ = v − ĀσA  (Ā = mean, σA = standard deviation)

Re-expresses each value as "how many standard deviations from the mean." Great when you don't know the true min/max, or there are outliers. (A variant swaps σ for the mean absolute deviation sA, which is more robust to outliers.)

Decimal scaling v′ = v10j,   j = smallest integer with max(|v′|) < 1
Remember the 3 scalers: Min-max = squeeze into a range (needs min & max) · Z-score = “how many σ from the mean” (needs mean & σ) · Decimal = slide the decimal point until |v|<1, so j = number of digits in the biggest |value|.

Just slide the decimal point left until every value is below 1 in magnitude. Simplest to do by hand.

✍️ Worked example — normalize {200, 300, 400, 600, 1000}
(a) Min-max to [0, 1]. min = 200, max = 1000, so v′ = (v−200)/(1000−200) = (v−200)/800. → 0, 0.125, 0.25, 0.5, 1. (Check: (300−200)/800 = 0.125 ✓.)
(b) Z-score. Mean Ā = (200+300+400+600+1000)/5 = 500. Std σ = √[ (Σv²)/5 − Ā² ] = 282.84. v′ = (v−500)/282.84 → −1.06, −0.71, −0.35, 0.35, 1.77. (Check: (200−500)/282.84 = −1.06 ✓.)
(c) Z-score with mean absolute deviation. s = (|200−500|+|300−500|+|400−500|+|600−500|+|1000−500|)/5 = (300+200+100+100+500)/5 = 240. v′ = (v−500)/240 → −1.25, −0.83, −0.42, 0.42, 2.08.
(d) Decimal scaling. Largest magnitude is 1000; divide by 10³ = 1000. → 0.2, 0.3, 0.4, 0.6, 1.0.
⚠️ The decimal-scaling subtlety (know this!) Strictly, decimal scaling needs max(|v′|) < 1. Here 1000/1000 = 1.0, which is not strictly below 1 — so a purist would use j = 4 → 0.1. But the standard textbook answer uses j = 3 → 1.0 (treating it as ≤ 1). Give the textbook's j = 3 answer, and if you have room, note the <1 technicality — it shows you understand the rule.
✍️ Worked example — normalize a single value (age = 35)

The age attribute has min = 13, max = 70, mean ≈ 29.96, σ = 12.94.

Min-max to [0, 1]: (35 − 13)/(70 − 13) = 22/57 = 0.39.
Z-score: (35 − 29.96)/12.94 = 5.04/12.94 = 0.39.
Decimal scaling (max 70 → j = 2, divide by 100): 35/100 = 0.35.
Which to prefer? Decimal scaling is often nicest here — it keeps the data intuitive and, unlike min-max, doesn't break if a future age falls outside 13–70 (min-max would throw an "out of bounds" because new values could exceed the fixed max).

CS1 Define data mining. (Give the four key adjectives.)short
Data mining is the extraction of interesting — non-trivial, implicit, previously unknown and potentially useful — patterns or knowledge from huge amounts of data. It is also called knowledge discovery from data (KDD).
CS2 Differentiate data mining from a database query, with an example.short
A query retrieves facts that are already stored and known — e.g. looking up a phone number in a directory. Data mining discovers previously unknown patterns — e.g. finding that certain surnames cluster in certain regions. In short: a query returns the known; mining uncovers the implicit.
CS3 List the steps of the KDD (knowledge discovery) process.short
1. Data cleaning, 2. Data integration, 3. Data selection, 4. Data transformation, 5. Data mining (the core step), 6. Pattern evaluation, 7. Knowledge presentation. Steps 1–4 are preprocessing; data mining itself is one essential step of the whole pipeline.
CS4 Describe the multi-dimensional view of data mining.short
Data mining is interdisciplinary and can be viewed along four dimensions: the data to be mined (relational, warehouse, transactional, streams, text/web, social), the knowledge/functions (characterization, association, classification, clustering, outlier analysis), the techniques used (machine learning, statistics, pattern recognition, visualization), and the applications (retail, telecom, banking, fraud, biology).
CS5 Distinguish classification from clustering.short
Classification is predictive and supervised: classes are predefined and the training data is labelled; it learns a model to assign new records to a known class. Clustering is descriptive and unsupervised: there are no predefined classes — it groups objects purely by similarity, so the groups emerge from the data.
CS6 Name the origins of data mining and the challenges it must address.short
It draws on machine learning / AI, pattern recognition, statistics, and database systems. Beyond those it must handle the enormity (volume) of data, its high dimensionality, and its heterogeneous, distributed nature.

Chapter 1 · Long questions recall

CL1 Explain the two categories of data-mining tasks and give the tasks under each.theory
Predictive tasks use some attributes to predict the unknown or future value of another attribute — these are classification (predict a categorical class), regression (predict a real number), and deviation/anomaly detection. Descriptive tasks find human-interpretable patterns that summarise the data — these are association discovery (dependency rules between items), clustering (natural groupings), and summarization (a compact description). Predictive tasks need a target/label; descriptive tasks do not.
CL2 Explain classification with the decision-tree example, naming training vs test set.theory
Classification builds a model for a class attribute as a function of the other attributes. From a training set (records whose class is known) it learns a classifier — e.g. a decision tree that splits on Refund, then Marital status, then Taxable income to decide "Cheat = Yes/No". A held-out test set (records whose true class is known but hidden from training) measures accuracy. A new, unlabelled record is then pushed down the tree from the root to a leaf, which gives its predicted class. Because the classes are predefined and the data is labelled, classification is supervised.
CL3 What is association rule discovery? Illustrate with market-basket analysis.theory
Given records that each contain some items from a collection, association mining produces dependency rules predicting the occurrence of one item from others. The classic setting is market-basket analysis: from transactions such as {Bread, Coke, Milk}, {Beer, Bread}, {Beer, Coke, Diaper, Milk}, the miner finds rules like {Milk} → {Coke} and {Diaper, Milk} → {Beer}. Retailers use such rules for product placement and recommendations. It is a descriptive task.

Part B — Short questions 5 marks

S1 Distinguish between a data object and an attribute, with an example.short
A data object is a single row — one entity you're studying, e.g. one student. An attribute is a single column — one property of that entity, e.g. the student's age. Objects are also called samples, instances, records or tuples; attributes are also called features, dimensions or variables.
S2 Differentiate between interval-scaled and ratio-scaled attributes.short
Both are numeric with ordered, equal-sized steps. The difference is the zero point: an interval attribute has no true zero (0 °C does not mean 'no temperature'), so ratios are meaningless. A ratio attribute has a true zero meaning 'none' (0 kg = no weight), so statements like '10 kg is twice 5 kg' are valid.
S3 Distinguish symmetric from asymmetric binary attributes.short
In a symmetric binary attribute both states are equally important and interchangeable — e.g. gender. In an asymmetric one, a rare or significant outcome carries the meaning and is coded 1 — e.g. a positive disease test. This matters because asymmetric distance measures discard the 0-0 matches (t).
S4 Why is the median preferred to the mean for skewed data?short
Because the median is robust to extreme values. The mean is a balancing point, so a single very large value drags it toward the tail and misrepresents the typical case. The median depends only on position in the sorted order, so extremes barely move it.
S5 State the outlier rule based on the IQR.short
A value is treated as a suspected outlier if it lies more than 1.5 × IQR beyond a quartile — that is, below Q1 − 1.5·IQR or above Q3 + 1.5·IQR.
S6 What is the five-number summary, and what does a boxplot show?short
The five-number summary is min, Q1, median, Q3, max. In the boxplot the box spans Q1→Q3 (the IQR), the line inside marks the median, the whiskers extend to the furthest points within 1.5×IQR, and anything beyond is plotted individually as an outlier.
S7 Distinguish a data matrix from a dissimilarity matrix.short
A data matrix holds the raw values: n objects × p attributes, so rows and columns are different kinds of thing — it is two-mode. A dissimilarity matrix holds distances between every pair of objects: n × n, objects on both axes — it is single-mode. Only the lower triangle is stored because d(i,j) = d(j,i) and d(i,i) = 0.
S8 Why does the asymmetric binary measure ignore t?short
Because a 0-0 match carries no information when the attribute is rare. If two patients both lack a rare disease, that agreement is shared by almost the whole population, so counting it would make every pair look similar. Asymmetric measures reward shared presence (q) against mismatches (r, s) only.
S9 Name the three special cases of the Minkowski distance.short
h = 1 → Manhattan (city-block, L₁) distance. h = 2 → Euclidean (L₂) distance. h → ∞ → supremum (Chebyshev, Lmax) distance, which equals the largest single coordinate difference.
S10 When would you use cosine similarity rather than Euclidean distance?short
For document / term-frequency vectors, where the direction of the vector matters but its length does not. A long and a short document about the same topic have very different Euclidean distance but nearly identical cosine similarity, because cosine compares the angle between vectors, not their magnitude.

The mean uses every value, so a few extreme values (outliers) drag it toward the tail. The median is the positional middle, so it barely moves — it's robust. That's why we quote median income, not mean.
T5 State the four properties that make a distance a "metric".theory
(1) Non-negativity: d(i,j) ≥ 0. (2) Identity: d(i,i) = 0. (3) Symmetry: d(i,j) = d(j,i). (4) Triangle inequality: d(i,j) ≤ d(i,k) + d(k,j). (Some texts merge (1)+(2) as "positive definiteness" and quote three — either is accepted, but Han & Kamber list four.)
M1 For {2, 4, 4, 4, 5, 5, 7, 9}: find mean, median, mode, range, variance, std-dev, Q1, Q3, IQR, and any outliers.math
1. The data is already sorted and there are N = 8 values.
2. Mean: add them → 2+4+4+4+5+5+7+9 = 40, then ÷ N → 40 ÷ 8 = 5.
3. Median: N is even, so average the two middle (4th & 5th) values → (4 + 5) ÷ 2 = 4.5.
4. Mode: the value that repeats most is 4 (it appears 3 times) → 4.
5. Range: max − min = 9 − 2 = 7.
6. Variance: take each value minus the mean 5 → −3, −1, −1, −1, 0, 0, 2, 4.
7. Square them → 9, 1, 1, 1, 0, 0, 4, 16; the sum is 32. So σ² = 32 ÷ 8 = 4.
8. Std-dev: σ = √(variance) = √4 = 2.
9. Quartiles: lower half {2,4,4,4} → Q1 = 4; upper half {5,5,7,9} → Q3 = 6; so IQR = 6 − 4 = 2.
10. Outliers: fences = Q1 − 1.5·IQR = 1 and Q3 + 1.5·IQR = 9. Every value lies in [1, 9] → none.
M2 From M1 (mean 5, median 4.5, mode 4), is the data skewed? Which way?math
1. Line up the three centres: mean = 5, median = 4.5, mode = 4.
2. Put them in order → mode (4) < median (4.5) < mean (5).
3. Rule: when mean > median > mode, the long tail points to the right.
4. So the distribution is right-skewed (positive).
5. Why: the big values 7 and 9 drag the mean upward, above the bulk of the data.
6. Cross-check (empirical rule): mean − mode = 5 − 4 = 1.
7. And 3 × (mean − median) = 3 × (5 − 4.5) = 3 × 0.5 = 1.5.
8. Both come out positive and close → consistent with a right skew. ✓
M3 Two objects have 6 asymmetric binary attributes with counts q = 3, r = 1, s = 2, t = 0. Find the Jaccard similarity and the asymmetric distance.math
1. Given: q = 3 (both 1), r = 1 (only the first is 1), s = 2 (only the second is 1), t = 0 (both 0).
2. These are asymmetric attributes, so we ignore t — the 0-0 matches don't count.
3. Jaccard similarity formula: J = q ÷ (q + r + s).
4. Work out the denominator: q + r + s = 3 + 1 + 2 = 6.
5. J = 3 ÷ 6 = 0.5.
6. Asymmetric distance = (r + s) ÷ (q + r + s) = (1 + 2) ÷ 6 = 3 ÷ 6 = 0.5.
7. Check: distance should equal 1 − Jaccard → 1 − 0.5 = 0.5. ✓
8. Note: t = 0 here, but even if t were 100 the answers wouldn't budge — that's the whole reason we use the asymmetric formula.
M4 For i = (2, 3, 5) and j = (4, 0, 9), compute Manhattan (L1), Euclidean (L2) and supremum (L∞) distances.math
1. Given two 3-D points: i = (2, 3, 5) and j = (4, 0, 9).
2. First find the difference in each coordinate: |2 − 4| = 2, |3 − 0| = 3, |5 − 9| = 4.
3. Manhattan (L1) = just add the absolute differences → 2 + 3 + 4 = 9.
4. Euclidean (L2) = √(sum of the squared differences).
5. Square each difference: 2² = 4, 3² = 9, 4² = 16.
6. Add them up: 4 + 9 + 16 = 29.
7. L2 = √29 ≈ 5.39.
8. Supremum (L∞) = the single biggest difference = max(2, 3, 4) = 4.
9. Sanity check: it's always true that L∞ ≤ L2 ≤ L1 → 4 ≤ 5.39 ≤ 9. ✓
M5 Find the cosine similarity of d1 = (5,0,3,0,2,0,0,2,0,0) and d2 = (3,0,2,0,1,1,0,1,0,1).math
1. Formula: cosine = (d1 · d2) ÷ (‖d1‖ × ‖d2‖).
2. Dot product: multiply matching entries — only positions where both are non-zero add anything.
3. = 5·3 + 3·2 + 2·1 + 2·1 = 15 + 6 + 2 + 2 = 25.
4. ‖d1‖ = √(25 + 9 + 4 + 4) = √42 ≈ 6.481.
5. ‖d2‖ = √(9 + 4 + 1 + 1 + 1 + 1) = √17 ≈ 4.123.
6. Denominator = 6.481 × 4.123 ≈ 26.72.
7. Cosine = 25 ÷ 26.72 ≈ 0.94.
8. Meaning: 0.94 is almost 1 → the documents point in nearly the same direction → highly similar.

Part D — Data preprocessing cleaning · normalization · reduction

S2 List the methods for handling missing values.short
Ignore the tuple; fill in manually; use a global constant; use the attribute mean/median; use the class-wise mean/median; use the most probable value (regression, Bayesian inference or decision tree). Best = most-probable-value; not recommended = global constant.
S3 Differentiate equal-width and equal-depth binning.short
Equal-width bins each span the same value range (interval), so counts can vary. Equal-depth (equal-frequency) bins each hold the same number of values, so ranges can vary.
S4 What is normalization and why is it needed?short
Normalization rescales an attribute's values to a common range (e.g. [0,1]). It's needed so that attributes with large units (like income) don't dominate distance/mining calculations over small-unit attributes (like age); it gives every attribute equal weight.
S4b What are the value ranges of the three normalization methods? (Han & Kamber Q2.5)short
Min-max → exactly the chosen [new_minA, new_maxA] (commonly [0, 1]); it maps the observed min→new_min and max→new_max. Z-score → not bounded; values are re-centred to mean 0 with standard deviation 1, so most fall roughly in [−3, +3] but any real value is possible. Decimal scaling → the open interval (−1, 1), since we divide by 10j until every |v′| < 1.
S5 Name the issues to consider during data integration.short
Schema integration / entity identification (matching equivalent entities across sources), redundancy (derivable or duplicated attributes, detected by correlation analysis), and detection & resolution of data value conflicts (differences in units, scale or encoding).
L2 Normalize {200, 300, 400, 600, 1000} using (a) min-max to [0,1], (b) z-score, (c) z-score with mean absolute deviation, (d) decimal scaling.long
(a) Min-max: v′=(v−200)/(1000−200)=(v−200)/800 → 0, 0.125, 0.25, 0.5, 1.
(b) Z-score: mean = 500; σ = √[(Σv²)/5 − 500²] = 282.84; v′=(v−500)/282.84 → −1.06, −0.71, −0.35, 0.35, 1.77.
(c) MAD z-score: s = (300+200+100+100+500)/5 = 240; v′=(v−500)/240 → −1.25, −0.83, −0.42, 0.42, 2.08.
(d) Decimal scaling: divide by 10³ → 0.2, 0.3, 0.4, 0.6, 1.0 (textbook j=3; strictly <1 would need j=4).

L5 What is data reduction? Describe its strategies, and the four sampling techniques.long
Data reduction yields a much smaller representation that produces almost the same mining results. Strategies: dimensionality reduction (attribute subset selection — forward selection, backward elimination, combination; or PCA/wavelets), numerosity reduction (parametric: regression/log-linear models; non-parametric: histograms, clustering, sampling), and data compression.
Sampling: SRSWOR (random, no repeats), SRSWR (random, repeats allowed), cluster sampling (pick whole pre-existing groups), stratified sampling (sample proportionally from each stratum so all groups are represented).
L6 Explain redundancy detection in data integration using correlation, and interpret r = 0.82 for age vs body-fat.long
Redundant attributes are ones derivable from or moving with others; keeping both wastes space and can bias mining. For numeric attributes we compute the Pearson coefficient r = Σ(aᵢ−Ā)(bᵢ−B̄)/(nσAσB), which lies in [−1,+1]. r > 0 → positively correlated (candidate redundant); r = 0 → independent; r < 0 → negatively correlated. For nominal attributes we use χ² instead.
r = 0.82 (age vs %fat) is strongly positive: as age rises, body-fat % tends to rise, so the two carry overlapping information and one could be dropped. Their covariance is also positive. (Correlation ≠ causation.)
